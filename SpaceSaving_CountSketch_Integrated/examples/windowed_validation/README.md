# 區塊視窗的手算驗證

此案例沿用現有 BlockWindowedSpaceSaving，不修改核心演算法。固定 W=8、B=2、M=4、Top-1，每區塊 4 筆資料、2 個計數器。

從整合目錄執行：

```sh
make test
make windowed-walkthrough
```

或從 repo 根目錄執行：

```sh
make -C SpaceSaving_CountSketch_Integrated test windowed-walkthrough
```

只需要 C++17 編譯器及 make，不需要 Python。測試中的檢查不依賴 assert，因此開啟 NDEBUG 也會執行。

## 輸入與預期

`shift.txt`：四個 1、三個 2、一個 3，接著八個 4。第 8 筆時 Top-1 為 1；第 9 筆開始取代最舊區塊，此時不能查詢；第 12 筆完成新區塊，視窗為第 5–12 筆，來源 1 不再出現，Top-1 為 4；第 16 筆時只有來源 4，其頻率區間收斂為 [8,8]。

`replacement.txt`：來源 1–8 各一次，接著來源 9 八次。前兩區塊各有四個不同來源，但每區塊只有兩個計數器，必須發生替換。第 8 筆的真實頻率全部平手，未見項目上界為 2+2=4，不能認證唯一 Top-1；第 12 筆來源 9 成為熱門來源，第 16 筆舊區塊全部淘汰。

## 驗證內容

- 逐筆核對結構及查詢可用性；未填滿或未到區塊邊界時必須拒絕查詢。
- 在第 8、12、16 筆，直接從原始資料最後八筆重算每來源頻率，再核對 FIFO 精確基準。
- 對來源 1–9（包含視窗內已不存在的來源）檢查合併上下界；不在候選集合的來源以 [0,U_unseen] 驗證。
- 核對手算 Top-1、舊來源淘汰、流量排名切換及集合認證。

輸出：[查詢結果表](../../results/validation/WALKTHROUGH_ZH.md)、[逐來源頻率與界限 CSV](../../results/validation/window_bounds.csv)。程式在兩組案例全部通過後才寫結果。

這是可解釋的功能驗證，不是新演算法、效能實驗或真實流量評估。核心演算法已有隨機差分測試；本案例補上可用於報告的逐步解釋及固定預期，不取代既有測試。
